# 지식베이스 검색 측정 (E-D, 빌더 계획 §3.3)

`uv run python bench/kb_eval.py`가 만든 파일. 손으로 고치지 말 것.

- 지식베이스: FAQ 80개, 문서 조각 51개 (`bench/data/kb/`, 합성).
- 질문: 답 있음 88+87, 답 없음 31+31, 블록 32+31 (개발용+확인용). 임계값은 개발용 절반에서 고르고 아래 표는 확인용 절반 값이다. [괄호]는 부트스트랩 95% 구간.
- NLU(샘플 봇, 새 세션) 규칙 분포: {'fallback': 226, 'intent': 74}. NLU 벡터 재사용 확인: 하네스 인코딩과의 최대 차이 0.0000.

기준: Recall@3 ≥ 0.9, 답 없는 질문 폴백 ≥ 0.9, 가로채기 각각 ≤ 0.05, p95 ≤ 100ms (문서 조각 10000개, 질문 벡터는 NLU 것을 재사용해 시간에서 뺌). 두 절반 전체의 Recall@3/MRR(참고): embedding 0.966/0.931, bm25 0.840/0.781, hybrid 0.931/0.863, hybrid+rerank 0.983/0.945, embedding+judge 0.966/0.931.

판단 규칙(코사인): FAQ 1위가 FAQ 기준 이상이면 그 답, 아니면 문서 1위가 문서 기준 이상이면 그 조각, 아니면 답하지 않음. 판단 규칙(embedding+judge): 임베딩으로 고른 FAQ 3개 + 문서 조각 3개를 재순위 모델이 채점해 최고점이 기준 이상이면 그 후보로 답한다. 블록이 확실한 질문은 FAQ 1위가 블록의 가장 가까운 예문 유사도보다 0.05 이상 높을 때만 지식베이스. 답 없는 질문은 폴백이나 되묻기로 끝나면 성공. 값을 기다리는 중의 규칙은 새 세션 측정이라 다루지 않는다.
