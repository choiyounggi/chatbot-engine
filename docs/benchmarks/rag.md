# 생성형 RAG 측정 (E-F)

`uv run python bench/rag_eval.py`가 만든 파일. 손으로 고치지 말 것.

- 질문·지식베이스·검색과 판단은 `docs/benchmarks/kb.md`와 같음. 지식베이스가 답한 질문 111개 중 제목이 정확히 같은 0개를 뺀 질문에만 생성(엔진도 같음).
- 엔진과 같은 조건: 생성이 3.5초(`LLM_TIMEOUT`)를 넘으면 시간 초과로 보고 자료를 보여 줌. 양쪽 모두 "출처: …" 줄을 빼고 비교.
- 표는 확인용 절반, [괄호]는 부트스트랩 95% 구간. 설정은 개발용 절반만 보고 고른다(확인용 절반은 고른 뒤에 계산).
- **맞게 답함** = 답이 사실(명사·숫자·내용 있는 용언 어간·부정)을 하나 이상 말하고, 그 사실의 60% 이상과 숫자 전부가 맞는 출처(정답 FAQ 항목, 정답 증거가 든 조각)에 있음. 문자열로 세므로 바꿔 말한 맞는 답을 틀렸다고 볼 수 있다 — 아래 '엇갈린 질문'에 채택 설정의 사례를 모두 싣는다.
- **근거 없는 부정** = 답한 것 중 답에 부정(않·안·못·없·아니·불가)이 있는데 맞는 출처 어디에도 부정이 없는 비율. 뒤집힌 답과 모델이 추론한 "아니요"가 섞여 있어 사람이 읽어야 구분된다.
- **재현율(참고)** = 정답 문장의 사실 60% 이상이 답에 있음 — 처음 쓴 지표. 짧고 맞는 답("나쁨입니다.")을 틀렸다고 보고 정답 문장을 그대로 내는 추출형만 유리해서 고르는 데 쓰지 않음.
- 생성을 버렸을 때(NO_ANSWER, 근거 없는 숫자, 너무 김, 빈 답): extract = 추출형 답을 보여 줌, fallback = 답하지 않음(폴백). LLM이 답하지 못했을 때(시간 초과, 오류)는 둘 다 추출형 답을 보여 줌.

## 결정
- 개발용 절반에서 기준을 모두 통과한 설정이 없어, 놓친 기준이 가장 적은 Qwen3-8B-4bit · k=1 · extract을 고른다.
- 같은 질문끼리 보면(개발용) 맞게 답함 차이의 구간 하한이 -0.045이다: 추출형보다 최대 0.045 낮을 가능성을 이 표본으로는 배제하지 못한다(기준 0.02보다 넓은 구간 — 질문 수의 한계). 틀리게 답함 차이 구간은 [-0.023, +0.057].
- 엔진 기본값: 자료 1개(`GENERATION_DEPTH`), 생성을 버리면 extract(`ON_REJECT`) — 이 결과와 같다. 모델은 운영자가 `--llm-model`로 정하고, 생성은 봇마다 지식베이스 설정으로 켠다(기본 꺼짐).
